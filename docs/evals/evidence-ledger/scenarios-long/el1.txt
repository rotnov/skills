== D1: Jobber changelog, 4.2
Jobber changelog, 4.2

Released 2026-10-28. This is a minor release; no schema migrations are required when upgrading from 4.1.x. Python 3.9 is no longer supported. The minimum supported Python version is now 3.10.

New features

Added a --dry-run flag to the jobber schedule command, which prints the parsed cron expression and the next five run times without registering anything (871).
The web dashboard now shows job tags in the list view and lets you filter by tag (880).
Structured log output can be switched to logfmt with JOBBER_LOG_FORMAT=logfmt (886).

Bug fixes

Fixed a crash in the dashboard when a job name contained non-ASCII characters (874).
Fixed duplicate execution when two workers poll simultaneously (902). Workers now take a session-level advisory lock on the job id before claiming the job.
Corrected the timezone shown in the "next run" column for schedules defined with an explicit tz argument (905).
Fixed a typo in the jobber --help output for the purge subcommand (911).

Deprecations

The jobber.contrib.slack notifier is deprecated and will be removed in 5.0. Use the generic webhook notifier instead; an example config is in docs/notifiers.md.
The JOBBER_LEGACY_UI setting no longer has any effect and will be removed in the next minor release.

Documentation

The quickstart guide was rewritten and now covers Docker Compose setups.
Added a page describing how to write custom serializers.

Thanks to the twelve contributors who sent patches for this release, including four first-time contributors.

== D5: Internal wiki, PgBouncer notes
Internal wiki, PgBouncer notes

Last edited by the platform team. These notes are a working reference, not an official runbook; corrections are welcome in the team channel.

Where things live: the main configuration file is pgbouncer.ini, and the user list sits in userlist.txt next to it. Both are templated by configuration management, so hand edits on a host will be overwritten on the next run. The listener port is 6432 on all hosts, which keeps it distinct from the database port 5432.

Pool modes: PgBouncer supports three modes, chosen per pool via pool_mode. The behaviour notes below come from the upstream documentation and are kept short on purpose.

Transaction pooling: a server connection is assigned per transaction and returned afterwards. Session state does not persist between transactions. SET, LISTEN, prepared statements and session-level advisory locks are unsafe or ineffective in this mode.

Admin console: connect to the virtual database named pgbouncer as one of the users listed in admin_users. SHOW POOLS, SHOW CLIENTS and SHOW STATS are the commands people reach for most often. RELOAD rereads the configuration without dropping clients.

Sizing: default_pool_size is set to 20 on the reporting cluster and 40 on the billing cluster. Raise these only after checking max_connections on the database side.

Monitoring: the exporter scrapes the admin console every 15 seconds. Dashboards are in the shared Grafana folder.

Open questions: whether to move the reporting cluster to the newer packaged build next quarter. Ping Marta before changing anything here.
