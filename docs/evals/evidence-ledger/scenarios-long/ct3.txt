== D4: Requirements
Requirements
Ingest service, Q1 platform work. Owner: data platform team. Last edited Tuesday after the sync with storage.

This page collects the requirements we agreed on for the components being swapped or added to the ingest service this quarter. Each section lists the constraints first and any notes underneath. Please add comments inline rather than editing someone else's notes, and tag the section owner if something changes.

Message queue client
Must support consumer groups and manual offset commits; reconnect with backoff capped at 30 seconds. Notes: current client is fine, revisit only if we change brokers.

Schema validation library
JSON Schema draft 2020-12 support; throughput at least 25k docs/s; Apache or MIT licence. Notes: Vesta is MIT and passes our golden set, which uses 2020-12 features. Quill is Apache.

Structured logging
JSON output with request ID and tenant fields; log level configurable at runtime without a restart. Notes: the existing logger already does most of this, needs a small wrapper.

Metrics
Prometheus endpoint; per-tenant counters for accepted and rejected batches; histogram of end-to-end ingest latency. Notes: dashboards will be rebuilt by the observability folks once the names are stable.

Deployment
Container image under 400 MB; health and readiness probes; config via environment variables only.

Open items
Storage team to confirm retention for the dead-letter bucket. Next review is in the Thursday platform slot; bring any blockers to that meeting or post them in the channel beforehand.
