== D3: Vela documentation, HTTP/3
Vela documentation, HTTP/3

Last updated 4 November 2026. This page belongs to the Protocols section of the Vela CDN guide. Related pages cover TLS certificates, origin shielding and cache key configuration.

To turn the feature on, open the Vela console, choose your property, and go to Settings, then Network. The HTTP/3 toggle sits below the TLS minimum version selector. Changes are saved per property and propagate to edge configuration within a few minutes. Accounts on the Starter plan will see the toggle greyed out until they upgrade; Business and Enterprise plans include it at no extra charge.

HTTP/3 is negotiated only when the client supports it; other clients continue on HTTP/2 unchanged. Gains come mainly from removing head-of-line blocking under packet loss and from faster handshakes on new connections.

Access logs include a field named proto_version, which records the protocol used for each request. You can filter on this field in Log Explorer or export it through the standard log streaming integrations, including S3 and BigQuery. The field was added in release 4.12 alongside the new edge_region column.

Terraform users can manage the setting with the http3_enabled attribute on the vela_property resource, available in provider version 2.8 and later. The Vela API exposes the same setting under the network object.

If you have questions about this page, contact your account team or open a ticket from the console Help menu. Documentation feedback can be sent with the thumbs icon at the bottom of every page. For details on regional data residency, see the Compliance section.
== D4: Traffic profile, enterprise API
Traffic profile, enterprise API

Prepared by the Platform Analytics group for the quarterly account review. Data window: 1 August to 31 October, drawn from the gateway request logs and the billing export. Figures are rounded; raw queries are stored in the analytics repository under the enterprise-profile folder. Questions about methodology should go to the analytics channel rather than to individual authors, since the rota changes weekly.

Scope: this profile covers the 41 accounts on the enterprise contract tier. Sandbox keys, internal test harnesses and the partner reseller programme are excluded. Two accounts migrated tiers during the window and are counted only from their migration date.

92% of requests originate from customer data centres over long-lived keep-alive connections. Measured packet loss on these paths: below 0.05%.

Endpoint mix: the orders and inventory endpoints together account for roughly two thirds of billable calls. Webhook registration calls remain a small share and are unchanged from last quarter. The bulk export endpoint shows the highest growth, up 18% quarter on quarter, driven mainly by three retail accounts onboarding their reporting teams.

Authentication: 87% of keys are scoped service tokens; the remainder still use legacy account-wide keys. Customer Success has agreed to contact the owners of those legacy keys before the January deprecation notice.

Error codes: 4xx responses are dominated by 429 rate-limit responses on two accounts that have exceeded their contracted quota; Account Management is handling the conversation about upgrades.

Next refresh is scheduled for early February. Please flag any accounts that should be added to or removed from scope before then.
== D5: Client inventory
Client inventory

Maintained by Developer Platform. Last reviewed during the Q4 planning cycle; next review scheduled for the second week of January.

This page lists the client libraries we publish and support, along with ownership and housekeeping notes. It is meant as a quick reference for support engineers, solutions architects and anyone triaging a customer ticket that mentions a library by name. For contract terms, support tiers and escalation paths, see the Customer Success wiki instead. Nothing here changes what is written there.

Ownership: the Java SDK is owned by the Integrations squad, the Go SDK by Core Services, and the .NET SDK by the Partner Engineering pod. Each repository has a CODEOWNERS file, and on-call rotations are listed in the team directory.

The official SDKs (Java, Go, .NET) account for 88% of enterprise API calls. All three use HTTP clients that support HTTP/1.1 and HTTP/2 only. HTTP/3 support is not on the SDK roadmap this year.

Release cadence: all three libraries follow semantic versioning and ship minor releases roughly every six weeks. Patch releases go out as needed. Changelogs are published on the docs site the same day as each release.

Documentation: the quickstart guides were rewritten in September. The .NET guide still has two broken code samples in the pagination section. A fix is tracked in the docs backlog and should land before the holiday freeze.

Licensing: all SDKs are Apache 2.0. Third-party dependency audits run monthly, and the last audit flagged no issues.

Housekeeping: if you find a stale link or an outdated screenshot anywhere in the SDK docs, please report it in the #devplatform channel. Questions about this page go to the Developer Platform team lead.
