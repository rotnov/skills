== D4: Petrel 9.2 reference documentation
Petrel 9.2 reference documentation
Chapter 14: Server configuration parameters

This chapter lists configuration parameters alphabetically. Each entry gives the parameter name, its default value, and a short description. Parameter names are case-insensitive. Values may be set in petrel.conf or passed on the command line with the --set flag. For a guide to the configuration file format, see Chapter 3.

auth_method (default 'scram'). Authentication scheme used for password logins. Accepted values are 'scram', 'md5', and 'trust'. The 'md5' option is retained for older clients only.

idle_session_timeout (default 0). Terminates any session that has been idle for longer than the given number of milliseconds. A value of 0 disables the timeout.

lazy_vacuum (default off). Defers vacuuming a page until 20% of its tuples are dead. Reduces IO bursts. May increase table bloat by up to about 20%. Safe to toggle at runtime; reversible.

lc_messages (default 'en_US'). Language used for server log and error messages. Translations are currently available for twelve languages.

listen_port (default 6410). TCP port on which the server accepts client connections. Must be between 1024 and 65535 unless the server runs with elevated privileges.

log_line_prefix (default '%t [%p] '). A printf-style string prepended to each log line. Supported escapes include %t for timestamp, %p for process ID, and %u for user name.

max_connections (default 200). Maximum number of concurrent client connections. Three slots are reserved for superuser sessions.

Parameters beginning with the letters n through z continue in section 14.3. Deprecated parameters are listed separately in Appendix C.

Our trial record

This page collects short write-ups from the infrastructure team's ongoing trials so that anyone on rotation can see what is being tested and who owns it. Entries are added in rough chronological order; older ones are archived at the end of each quarter. Please keep each entry brief, link to the relevant ticket, and note the owner's initials.

Trial: shorter alert grouping window in the paging tool. Owner: MK. We cut the grouping window from five minutes to two for the staging environment only. Pages per week went from 14 to 17, mostly duplicates. Reverting next sprint.

Trial: storage setting. Owner: DS.

Node db-4 (production, same hardware and workload shard as the other five nodes) has run with lazy_vacuum = on for three weeks. Nightly p99 disk latency: 180 ms to 22 ms. Table bloat: 9% to 12%, stable. Query p95: unchanged.

Trial: switching the CI runners to the newer base image. Owner: AR. Build times on the main repository dropped from roughly 11 minutes to 8. Two flaky integration tests surfaced and are tracked in the CI backlog; neither appears related to the image itself.

Trial: weekly certificate expiry report. Owner: JL. The report now runs Monday mornings and posts to the ops channel. It caught one internal endpoint expiring within ten days, which has since been renewed.
