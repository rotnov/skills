== D2: Strand documentation excerpt
Strand documentation excerpt

Section 4: Core concepts

This section assumes you have completed the installation steps in Section 2 and can reach a running Strand cluster from your workstation. Examples use the strand command-line client, version 3.2 or later. Older clients will print a deprecation warning but still work for everything shown here. Topic names may contain lowercase letters, digits, hyphens and dots, and must be between 3 and 120 characters long. Names are case-sensitive in the API, but the web console displays them in lowercase. To list existing topics, run strand topics list; add --json for machine-readable output.

Topics are independent ordered logs. Strand provides at-least-once delivery per topic. There are no transactions spanning topics, or spanning Strand and an external database. Consumers must be idempotent and tolerate out-of-order arrival across topics.

4.1 Authentication

Every client connection must present a credential. Strand supports API keys and short-lived tokens issued by your identity provider through OIDC. API keys are convenient for local development but should be rotated at least every 90 days. The console shows a yellow badge on keys older than 60 days. Tokens default to a lifetime of one hour.

4.2 Observability

Each broker exposes metrics on port 9464 in Prometheus format. The bundled Grafana dashboard covers disk usage, connection counts, request latency and certificate expiry. Logs are written as structured JSON to standard output.

If you spot a broken link or an outdated example, open an issue in the docs repository and tag it docs-core.
