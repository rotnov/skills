== D6: Corvid vendor documentation
Corvid vendor documentation

Corvid agents run on Linux hosts with kernel 5.10 or later. Each agent requires 2 vCPUs and 4 GB of memory at minimum; larger fleets should allocate 8 GB to accommodate the metrics buffer. The agent listens on TCP port 7710 for control traffic and on port 7711 for the local health endpoint. Firewall rules should permit outbound HTTPS to the Corvid control plane in your selected region. Supported regions are currently us-east, eu-west and ap-south. Configuration lives in /etc/corvid/agent.yaml, and changes are picked up on the next service reload without a full restart.

Block snapshots are crash-consistent. restore.sh returning 0 indicates that the volume was attached and the engine started. It does not validate table contents.

Logging defaults to the INFO level and writes to /var/log/corvid/agent.log, rotating at 100 MB with seven files retained. Set log_level: debug in the configuration file when opening a support case, and revert it afterwards, as debug output can grow quickly on busy hosts. Licenses are issued per host and are checked against the control plane once every 24 hours; an agent that cannot reach the control plane continues to operate for a 14-day grace period. Upgrades are published on the second Tuesday of each month. Release notes, known issues and the deprecation schedule are available in the customer portal. For billing questions, contact your account manager rather than the support queue.
