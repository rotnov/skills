# Quorum authoring guidance

## 2026-10-21 — Coordinate with peer agents first

The owner asked to communicate with the teammate's Quorum agent first and involve
the human only when the agent does not answer. Route coordination through the
registered peer and inspect its response; an unanswered queue or a reported
human-action blocker permits fallback within the owner's existing messaging scope.

## 2026-10-21 — Connect concrete client sessions

The owner requires joining the actual existing Codex or Claude session to the
quorum. A dedicated headless pilot profile is not equivalent. Receiving, waking,
showing the peer message in that chat and returning that chat's answer are separate
acceptance boundaries. Do not report pairing complete from a worker-only exchange.

## 2026-10-23 — Named native quorum services Quorum mechanics

The owner corrected that a named native `quorum` worker creates and services the
authorized Quorum mechanics, including create, join and invite, and is selected
or reused before creation or setup begins, not only after accepting or receiving
tasks. `quorum` is the label and brief of a normal supported native worker; it
needs no custom provider agent definition or global configuration and no new
setup question. Routine reporting stays quiet. The actual parent chat keeps its
identity and alone runs bound session commands; a headless model or another
session is never a substitute.
